# CX83 Labs website continuous execution policy

Owner direction received October 9, 2026.

## Operating default

For authorized CX83 website tasks, keep making meaningful, independently verifiable progress within the active work session. Do not wait for an owner to approve routine planning, code improvements, test runs, pull requests, or protected staging deployments that fall inside the approved roadmap.

After completing one milestone, continue to the next independent milestone. Avoid unnecessary resets or repeatedly reopening accepted decisions. Prefer small, safe, working deployments and an accurate status receipt over leaving finished changes indefinitely in a draft pull request.

## Delivery gates still apply

1. Preserve all source work and approved assets. Read project HEAD and outstanding handoffs before starting.
2. Make scoped changes in GitHub, run typecheck, lint, integration and browser tests, and review representative desktop and mobile screenshots. Fix reported issues before merging.
3. Deploy verified changes to the existing **password-protected staging environment** through its normal pipeline; verify the deployed commit, health check, working pages and existing owner integrations.
4. Do not assert that a working source commit is deployed until staging actually confirms success.
5. Do not create broken or misleading public features merely to satisfy a request to ship quickly. If a real media file is missing, use a factual, working interim experience and leave the original media integration as a separate visible follow-up.
6. Never invent payment pricing, customer licensing, product release approval, testimonials, screenshots, recordings or service guarantees. Checkout activation, irreversible spend, legal terms and publishing to public production require relevant concrete authorization.
7. If one task needs unavailable files, credentials, external approvals or tools, record the precise blocker, continue parallel independent work, and ask only for essential owner input.
8. Do not treat an automation or a previous chat as permission to run an indefinite background process. Ongoing scheduled operations require an actual authorized scheduler and available credentials.

- **Phase 2:** Demonstration-led homepage; deploy a factual source-backed improvement now. Original v2 video/captions remain a follow-up until exact files can be inspected.

Keep a durable record in GitHub with PROJECT, HEAD, COMPLETED, BLOCKED, NEXT and ARTIFACTS. Distinguish draft, tested, merged, staged and production states. Customer support and privileged owner tools must remain separate.
